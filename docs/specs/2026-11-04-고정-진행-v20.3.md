# 고정 진행 v20.3 설계 (같은 씨앗 + 같은 조작이면 기기와 상관없이 같은 판)

- 날짜: 2026-11-04 · 상태: 설계 1부·2부 승인(「A」·「ㄱㄱ」·「ㄱㄱ」) → 설계서 검토
- 배경: LOG v20.2.1 「최근 커밋 검토」. v20.1의 「같은 씨앗이면 같은 판」이 장면 빠르기(fps)가 같을 때만 맞음 — 씨앗 12345·60초: 30fps 처치 42 / 60fps 393 / 144fps 131 / 10fps 279

## 1. 의도

게임 진행(`update`)을 장면 길이와 떼어 **늘 1/60초**씩 한다. 그러면 게임 상태는 「씨앗 + 진행 차례 + 그 진행 때의 조작」만으로 정해진다.

**한계(사용자에게 알림)**: 사람의 조작은 기록하지 않으므로, 사람이 한 판을 씨앗만으로 다시 볼 수는 없다. 같아지는 것은 자동 플레이·시험처럼 조작이 정해진 경우다. 조작 기록은 범위 밖.

## 2. 진행 규칙 (`src/js/13_render.js` 의 `frame()`)

| 이름 | 값 | 뜻 |
|---|---|---|
| `STEP` | 1/60 | 진행 한 번의 길이(늘 같음) |
| `FRAME_MAX` | 0.25 | 한 장면이 따라잡는 시간 상한(그대로) |
| `acc` | 0 이상 1/60 미만(진행 뒤) | 모아 둔 시간 |

1. 장면마다 `acc += min(FRAME_MAX, 장면 길이)`.
2. `acc ≥ STEP` 이고 판이 살아 있고 창이 없으면 `update(STEP)`, `acc −= STEP`, 그다음 기다리는 창 열기(지금과 같은 차례). 반복(한 장면 최대 15번).
3. 창이 열리거나 판이 끝나면 `acc = 0`(남은 시간 버림). `visibilitychange` 때도 `acc = 0`.
4. 진행이 없는 장면(120·144Hz)도 그리기·HUD·성능 감시는 지금처럼 한다(실제 시간).
5. 부동소수 쌓임 방지: 비교는 `acc + 1e-9 ≥ STEP`.

게임 상태를 바꾸는 일은 모두 `update` 안에서만 한다. `frame()` 안에서 `update` 밖에서 장면 길이로 게임 상태를 바꾸는 곳이 있으면 `update` 안으로 옮긴다(구현 때 찾음).

## 3. 확인 방법 (시험 먼저)

| 시험 | 보는 것 | 고치기 전 |
|---|---|---|
| `tests/unit/rng_det.test.js` 넓힘 | 같은 씨앗·같은 조작(진행 차례마다 정해진 방향)으로 10·30·60·144fps 60초: 처치·레벨·무기·퇴마사 자리·다음 난수가 모두 같음 | 실패해야 함 |
| `tests/unit/timestep.test.js` 고침 | 60·30·10·5·144fps 5초 → 게임 5초(±0.02) · 진행은 늘 1/60초 · 144fps는 장면마다 진행 0~1번 · 2fps는 장면마다 0.25초 · 창이 열린 뒤 시간이 더 흐르지 않음 | 1/60초·144fps 줄이 실패해야 함 |
| 새 `tests/unit/frame_only_update.test.js` | 진행이 없는 장면(1/144초 장면 하나)에서 게임 상태(시간·요괴 자리·난수)가 바뀌지 않음 | 실패해야 함 |

**성능**: `tests/browser/vfx_perf.py`를 v20.2.1과 번갈아 두 번씩. 기준: 고화질 켬 ≤ 33ms, 늘어난 시간 ≤ 3ms. 30fps 근처(진행 두 번)는 진행 한 번 시간을 따로 적는다. 넘으면 멈추고 의논.

**밸런스**: 6직업 × 2갈래 × 4판, 30fps·60fps 각각, v20.2.1과 비교 — 막별 받은 피해·보스 시간이 흔들림 안(60fps는 거의 같아야 함).

**마무리 묶음**: 단위 전부 · 브라우저 전부(`i18n_ko_same`·`ground_same`·`refine_same`은 인자 없이) · 자동 플레이 12판.
