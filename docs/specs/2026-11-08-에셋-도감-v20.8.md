# 에셋 도감 v20.8 설계 (코드로 그린 그림을 한곳에서 보고, README 그림을 늘 최신으로)

- 날짜: 2026-11-08 · 상태: 구상 질문 1~3 결정 · 1부 제시 → 사용자 「추천하는 방식대로 완료될 때까지 승인」(2부·3부는 추천안으로 정하고 이 문서에 적음)
- 결정 기록: 「첨부한 이미지(Asset Library)를 바탕으로 조선퇴마록의 에셋을 정리」 → A 에셋 도감 · 질문 1 「가 저장소 문서 + 플레이 사이트 페이지」 · 질문 2 「가 멈춘 그림 전부 + 바닥·효과는 막별 대표 한 장, 다듬기 켬/끔」 · 질문 3 「가 도감 도구가 docs/img도 같은 이름으로 다시 그림」

## 1. 문제

- 조선퇴마록의 그림은 모두 코드(글자 격자 + 팔레트)로 그린다. 그림 파일이 없어서 「무엇이 몇 장 있고 어떻게 생겼는지」를 한눈에 볼 곳이 없다(스팀 스토어 이미지 고르기, 도트 다듬을 곳 찾기, 남에게 보여 주기가 불편)
- README가 쓰는 `docs/img` 552장은 뽑은 스크립트가 저장소에 없다(시험 2개만 다시 그림). 도트를 고쳐도 README 그림은 옛 모습으로 남고, 새 과업 12개처럼 그림이 없는 것도 모른다

## 2. 의도

Asset Library처럼 **종류로 거르고, 이름으로 찾고, 격자로 훑고, 하나를 눌러 크게 보는** 도감 페이지. 그림은 **게임의 그리기 함수를 그대로 불러** 뽑아 게임 화면과 어긋나지 않는다. 명령 한 번으로 도감과 README 그림이 함께 새로 그려진다.

## 3. 결과물

```
tools/assets.py          ← 도구(실제 브라우저로 게임 파일을 열어 그리기 함수를 부름)
tools/assets_list.js     ← 그릴 목록과 그리는 법(게임 위에 얹어 실행, 단위 시험도 이것을 씀)
docs/assets/
  index.html             ← 도감 페이지(플레이 사이트 …/docs/assets/)
  assets.json            ← 그림 목록
  sheets/<종류>.png      ← 종류별 대표 시트(그 종류 전부 + 이름 밑글)
  img/<종류>/<id>.png    ← 다듬기 끔(원래 도트)
  img/<종류>/<id>@r.png  ← 다듬기 켬(v20.5 색조 테두리) — 다듬기를 쓰는 그림만
docs/img/<접두>_<id>.png ← README 그림(지금 이름·크기 그대로 다시 그림)
```

### 3-1. 종류 (지금 `docs/img` 접두와 게임 표)

| 종류 | 표 | README 접두 · 배율 | 다듬기 |
|---|---|---|---|
| 퇴마사·전직 | `CHARS`(차림 `look`, 갈래 × 차수 `tiers`) | `char_<cid>`·`char_<cid>_<nn>` ×4 · `charS_<cid>` ×2 | 켬/끔 |
| 요괴(보스·중간 보스 포함) | `EN` | `e_<id>` | 켬/끔 |
| 사람(NPC) · 하늘 손님 | `NPCS` · `SKY` | `npc_` · `sky_` ×3 | 켬/끔 |
| 펫 | `PETS` | `pet_` | 켬/끔 |
| 무기·진화·합공 | `WD`(type `w`) | `w_` ×4 | — |
| 직업 기술 | `WD`(type `c`) | `s_` ×4 | — |
| 보패 | `PD` | `p_` ×4 | — |
| 과업 휘장 | `TASKS`(`taskBadge`) | `task_` ×2 | — |
| 인장 · 담금질 · 변종 · 각성 · 이상 · 축복 · 짝 축복 · 갈림길 · 넋의 선물 · 도깨비 방망이 · 궁극기 · 기물 · 설화 · 난이도 | `SEALS`·`TEMPER`·`VARS`·`AWK`·`ANOM`·`BLESS`·짝 축복·`PATHS`·`GIFTS`·`DKB`·`KS`·`ULT`·`TALES`·난이도 표 | `seal_`·`tm_`·`var_`·`awk_`·`anom_`·`b_`·`c_`·`d_`·`path_`·`gift_`·`dkb_`·`ks_`·`u_`·`tale_`·`grade_`·`i_` | — |

- 표의 접두는 지금 파일에서 찾은 규칙이다. 구현 때 각 종류의 그리기 함수를 찾아 **지금 파일과 점 하나까지 같은지** 견주어 규칙이 맞는지 확인한다(아래 6장)
- 지금 파일 중 장면 캡처(`banner`·`hub`·`refine_*`·`arch`·`elite2_*`·`tier6_looks`·`qr_play` 등)는 도구가 만들지 않는다 → 「손으로 만든 그림」 목록으로 보고만 하고 지우지 않음

### 3-2. `assets.json` 한 줄

`{id, kind, name(한국어), nameZh(있으면), file, fileR(다듬기 켬, 있으면), readme(docs/img 경로, 있으면), w, h, scale, used(쓰이는 곳: 막·직업·짝 무기 등 표에 있는 것만), since(처음 보인 판)}`

- `since`: git 기록에서 그 id가 `src/`(초기 판은 `index.html`)에 `id:` 꼴로 처음 나온 커밋의 판 번호(커밋 글의 `vNN`). 첫 커밋(v9)에 이미 있으면 「v9 이전」, 못 찾으면 비움 — 추측하지 않음
- 이름·쓰이는 곳은 게임 표에서 그대로(손으로 쓰지 않음)

## 4. 도감 페이지 (`docs/assets/index.html`)

- 게임과 같은 어두운 바탕·글꼴, 바깥 라이브러리 없이 한 장(HTML+CSS+JS), `assets.json`을 읽어 그림
- **위 줄**: 이름·id 찾기 · 종류 고르기(개수 함께) · 크기(작게·보통·크게) · 바탕(체크·어둡게·밝게) · 다듬기(끔·켬) · 「n장」
- **왼쪽**(휴대폰은 위로 접힘): 종류 목록과 개수, 종류마다 「대표 시트」 링크
- **격자**: 칸마다 그림(픽셀 그대로 정수 배율, `image-rendering: pixelated`), 이름, `id · w×h`
- **눌러 크게 보기**: 큰 그림(다듬기 끔·켬 나란히), 종류·이름·id·크기·쓰이는 곳·처음 보인 판·README 경로, PNG 열기
- 주소에 상태를 남김(`#kind=e&q=도깨비`) → 링크로 같은 화면 공유 · 휴대폰 390px에서 옆 넘침 없음
- 게임 파일과 따로라 게임 크기·속도 그대로. `sw.js`는 `docs/assets/`를 오프라인 캐시에 넣지 않음(도감을 열어도 캐시가 수백 장 불어나지 않게)

## 5. 도구 (`tools/assets.py`)

- `python3 tools/assets.py` → 빌드된 `index.html`을 Playwright로 열고, 게임 함수(`charSpr`·`variants`의 `raw`/`ref`·`ICON`·`wIcon`·`taskBadge`·`artSpr`·`shieldSpr` 등)를 불러 캔버스를 PNG로 저장 · 정수 배율 확대(뭉갬 없음)
- 같은 입력이면 같은 파일(되풀이해도 git 차이 없음) · 끝에 보고: 종류별 장수, `docs/img`에서 **바뀐 그림 / 새 그림 / 같은 그림 / 손으로 만든 그림** 수와 이름
- `--check`: 파일을 쓰지 않고, 지금 `docs/img`·`docs/assets`가 게임과 어긋나는지만 봄(낡은 README 그림 찾기)

## 6. 확인 (시험 먼저)

| 시험 | 보는 것 |
|---|---|
| 단위 `assets_list` | 도감 목록 함수(`tools/assets_list.js`의 `assetList()`, 게임 코드는 건드리지 않고 도구가 게임 위에 얹어 씀)가 표의 모든 항목을 빠짐없이 한 번씩 · id 겹침 없음 · 이름이 빈 것 없음 · 종류마다 개수 = 표 개수 |
| 도구 첫 실행 | 지금 `docs/img`와 견주어 **같은 그림이 대부분**(규칙이 맞다는 증거) · 다른 것은 이름을 모두 보고하고 화면으로 확인(도트가 바뀐 것인지 규칙이 틀린 것인지) |
| 도구 두 번째 실행 | 파일이 하나도 바뀌지 않음(같은 입력 같은 출력) |
| 브라우저 `asset_page` | 도감 페이지를 휴대폰·PC로 열어: 전체 장수 = `assets.json` · 종류 고르기·찾기·다듬기 켬/끔·크게 보기·주소 공유가 동작 · 깨진 그림 0 · 옆 넘침 0 · 화면 오류 0 |
| 기존 | 단위 전부 · 브라우저 전부(하나씩) — 게임 코드는 바뀌지 않으므로(판 번호·`sw.js` 제외) 화면은 그대로여야 함 |
