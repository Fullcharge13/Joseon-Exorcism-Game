# 캐릭터·요괴 크기 (2배 정밀 그리기) · 설계

- 작성: 2026-10-20 · 대상 판: v17.1
- 상태: 설계 확정(사용자 확인 1·2부, 문서 승인). 2026-10-20 구현 중 1.5배 단계를 뺌(아래 0장 마지막 줄)

## 0. 정해진 것 (결정 기록)

| 질문 | 결정 |
|---|---|
| 무엇을 바꾸나 | **C**: 보이는 넓이는 그대로 두고, 캐릭터·요괴 그림만 크게 |
| 맞는 범위(판정) | **그림만 크게**. 판정은 그대로 두어 난이도·균형이 바뀌지 않음 |
| 그리는 방식 | **2배 정밀 그리기**(그리기 판을 가로·세로 2배로). 2배는 늘 도트가 깔끔하게 나옴 |
| 쓸 수 있는 기기 | **모든 기기**. 느려지면 저절로 기본 크기로 돌아감 |
| 크기 단계 | ~~기본 · 1.5배 · 2배~~ → **기본 · 2배**. 보스는 1.5배까지 |
| 1.5배를 뺀 까닭 (구현 중 발견) | 1.5배는 화면 배율 `S`가 짝수일 때만 깔끔하다. 흔한 PC(1920×1080 전체 화면 `S`=5, 1366×768 `S`=3)에서는 도트 한 칸이 7·8칸(4·5칸)으로 섞였다. 화면 해상도로 그려 맞추는 방법은 1920에서 11ms(가끔 21ms)로 무거웠다. 사용자 결정: **1.5배를 빼고 기본·2배만** |

## 1. 목적

PC 사용자, 특히 큰 화면에서 떨어져 앉아 하는 사용자가 캐릭터와 요괴를 알아보기 쉽게 한다. 지금 있는 「도트 크기」 설정은 그림을 키우면 보이는 넓이가 줄고, 요괴가 나오는 거리도 함께 줄어 난이도가 바뀐다. 새 설정은 보이는 넓이와 판정을 그대로 둔다.

## 2. 플레이어가 보는 것 (1부)

- **설정**: 「도트 크기」 아래에 「캐릭터·요괴 크기: 기본 / 2배」. 설명 「보이는 넓이는 그대로 두고 그림만 키웁니다. 맞는 범위는 바뀌지 않습니다.」
- **커지는 것**: 플레이어(1~5차 모든 차림·옷 빛깔), 펫, 도사 전우치, 일반·정예 요괴, 보스. 머리 위 체력 막대·표식(얼음·독·표적·정예 막대), 발밑 그림자도 커진 그림에 맞춘다.
- **보스**: 2배를 골라도 1.5배까지. 이무기·어둑시니·그슨대(따로 그리는 큰 보스)는 지금 크기.
- **그대로인 것**: 무기·투사체·장판, 아이템·구슬, 장애물, 피해 숫자, HUD.
- **판정**: 플레이어·요괴의 맞는 범위 값(`r`)을 바꾸지 않는다.
- **느려지면**: 지금의 느려짐 감지(1초 평균 24ms가 3번 이어짐)가 걸리면, 2배 정밀이 켜져 있을 때는 먼저 그것을 끄고 알림 「화면이 느려져 캐릭터·요괴 크기를 기본으로 돌렸다 (설정에서 변경)」. 감지를 처음부터 다시 하고, 그래도 느리면 지금처럼 절약 모드.
  - 저장된 선택은 바꾸지 않는다(다음 실행에서 다시 시도). 이번 실행에서 설정을 다시 고르면 다시 켜진다.
  - 성능 모드 「절약」(직접 고름 또는 자동 전환)이면 늘 기본 크기.
- **모드**: 본편·퇴마 원정·설화 출정 모두 같다. 제목 화면 배경 그림도 같은 방식으로 그린다.

## 3. 만드는 방법 (2부)

### 3-1. 저장

- `meta.set.ent`: `1 | 2`, 기본 1. 다른 값이면 1. 저장 판 번호(`saveVer`)는 그대로 두고 빠진 값만 채운다.

### 3-2. 2배 정밀 그리기

- `HD = meta.set.ent>1 && !LOW && !entOff` (`entOff`: 이번 실행에서 느려짐으로 끈 상태).
- `resize()`: HD면 그리기 판(`buf`)을 `2W × 2H`로. 보이는 넓이(`W·H`, 게임 단위)와 화면 배율 `S`는 그대로.
- `render()` 시작에서 HD면 `b.setTransform(2,0,0,2,0,0)`, 아니면 `(1,0,0,1,0,0)`. 그리기 판에서 픽셀을 직접 읽거나 쓰는 코드(`getImageData`·`putImageData`)는 없다(2026-10-20 확인). 무늬 칠하기(`createPattern`) 1곳과 글자 5곳은 변환을 그대로 따른다.
- `blit()`: 그리기 판 전체(`buf.width × buf.height`)를 화면 `W·S·DPR × H·S·DPR`에 옮긴다.
- 화면 캔버스(`ctx`)에 바로 그리는 것(장판 아이콘·피해 숫자·FPS)은 게임 좌표 × `S`라서 바뀌지 않는다.
- 측정용 시험 코드(버릴 코드)로 두 방식의 화면이 같고, 그리기 시간은 약 1.8배임을 확인했다(아래 5장).

### 3-3. 그림 배율 한 곳

```
entK(e)    → 그 그림을 몇 배로 그릴지
  플레이어·펫·전우치·일반·정예 요괴: HD ? meta.set.ent : 1
  보스(e.boss): HD ? min(meta.set.ent, 1.5) : 1
  이무기·어둑시니·그슨대 보스(proc): 1
```

- 요괴: `drawSpr(..., e.sc*entK(e), ...)`. 머리 위 표식 높이 `s.hgt*e.sc` → `s.hgt*e.sc*entK(e)`. 정예 체력 막대, 발밑 그림자 반지름도 곱한다.
- 플레이어: `drawHeroBody`·`drawHpBar`·`heroBox`(가림 측정·무기 뒤 그리기 판단)에 같은 배율.
- 펫(`drawPet`), 전우치(`drawJW`)도 같은 배율.
- 맞는 범위 `P.r`, `e.r`, 무기 사거리, 줍기 거리는 건드리지 않는다.

### 3-4. 느려짐 감지

`perfWatch`의 「3번 이어짐」 분기 앞에 다음을 넣는다.

```
if (HD) { entOff = true; resize(); pm.slow = 0; toast('화면이 느려져 캐릭터·요괴 크기를 기본으로 돌렸다 (설정에서 변경)'); return; }
```

설정에서 크기를 바꾸면 `entOff=false`.

## 4. 시험 (시험 먼저)

| 시험 | 확인할 것 |
|---|---|
| 단위 `ent_size` | 엉뚱한 `ent`(문자열·3·0) → 1 · `ent` 2면 `buf`가 `2W×2H`, 1이면 `W×H` · 플레이어 그림 폭이 2배 · 요괴 폭 2배 · 보스는 2배를 골라도 1.5배 · 이무기류 1배 · 투사체·아이템 그리기 크기 그대로 · `P.r`·`e.r` 그대로 · 머리 위 표식이 커진 그림 위에 있음 |
| 단위 `ent_perf` | 느린 프레임 3초 → `entOff`, 크기 기본, 절약 모드 아님, 저장된 `ent` 그대로 → 다시 느린 프레임 3초 → 절약 모드 · 절약 모드면 HD 꺼짐 · 설정을 다시 고르면 `entOff` 풀림 |
| 브라우저 `ent_size.py` | PC 1920×1080·1366×768·휴대폰에서 기본·2배 캡처(직접 확인) · 2배에서 플레이어 도트 한 칸의 화면 크기가 모두 같은지 기계 검사 · 화면 넘침·페이지 오류 0 · 그리기 시간(5장 표와 비교) |
| 회귀 | 단위 시험 전부, `tale_flow.py`, `pick_touch.py`, 가림 측정(무기가 캐릭터·체력 막대를 덮는 비율이 기본 크기에서 v17.0과 같음) |

## 5. 무게 측정 (2026-10-20, 버릴 시험 코드, 요괴 약 115~135마리·무기 6개 최대 레벨)

| 기기 | 지금 | 2배 정밀 |
|---|---|---|
| PC 1920×1080 | 1.6ms | 2.8ms |
| PC 1366×768 | 2.0ms | 3.6ms (가끔 18.7ms) |
| 휴대폰 고화질 | 4.5ms | 8.3ms |
| 보급형 휴대폰(CPU 4배 느림) | 24.9ms | 48.8ms |

그래픽 카드 없이 돌린 브라우저라 절대 시간은 실제와 다를 수 있다. 비율(약 1.8배)을 기준으로 본다.

## 6. 이번에 하지 않을 것

- 1.25배·1.5배처럼 깔끔하지 않은 단계 (보스는 원래 1.4·1.6배로 그리는 것이 있어, 2배일 때 1.5배 제한 보스는 지금처럼 칸이 섞일 수 있다)
- 무기·투사체·아이템 크기 조절
- 판정 크기 변경
- 「도트 크기」 설정 개편(정수 배율 간격 문제는 그대로)

## 7. 오류·예외

- 설정을 바꾸는 순간(게임 중 일시정지 화면에서): `resize()`를 다시 불러 그리기 판을 새 크기로.
- 화면 크기가 0인 경우(이전 v7 오류): 그리기 판 크기는 최소 1을 지킨다.
- 옛 저장: `ent`가 없으면 1.
