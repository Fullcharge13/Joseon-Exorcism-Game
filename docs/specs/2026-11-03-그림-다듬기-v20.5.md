# 그림 다듬기 v20.5 설계 (그래픽 패치 1부)

- 날짜: 2026-11-03
- 상태: 설계 승인(1부 그림 규칙 · 2부 구조·성능·설정·확인) → 설계서 검토 대기
- 판 번호: 처음 v20.0으로 적었으나 v20.0~v20.4가 다른 작업에 쓰여 **v20.5**로 바꿈(2026-11-05)
- 다음 판: 효과 다시 만들기(도깨비불·연기·장판을 잡음 방식으로 미리 굽기). 이 설계서의 범위 밖이며 따로 설계한다.

## 1. 의도

사용자 요청(원문): 「그래픽 패치 계획 : 2. 1번에 효과 다시 만들기 더하기」, 「A. 두 판으로 나누기」, 「A. 은은하게」.

지금 그림 다듬기(v18.5~v18.6.1, `refinePix`)는 테두리를 이웃 색 ×0.45로, 위 가장자리를 흰빛 18%로, 아래·오른쪽 가장자리를 ×0.8로 칠한다. 밝기만 바꾸므로 그림이 밋밋하다. v20.0은 **색조 이동**(어두운 쪽은 푸르게, 밝은 쪽은 노랗게)과 **빛 쪽·그림자 쪽이 다른 테두리**로 입체감과 색감을 더한다. 세기는 **은은하게**, 즉 지금 그림의 느낌을 지키는 쪽이다.

참고: github.com/mankidev/codixel(MIT, mankidev)의 `hueRamp`·`selout`·`rimLight` 생각을 빌린다. **코드와 그림은 가져오지 않고** 직접 쓴다. 출처는 LOG와 README 감사 글에 적는다.

## 3. 그림 규칙 (승인된 1부)

격자는 그대로이고, 다듬는 규칙만 바뀐다. 빛은 늘 **왼쪽 위**에서 온다. 뒤집힌 그림은 뒤집은 뒤에 다듬는다(지금과 같음).

| 자리 | 지금 | 새 규칙 |
|---|---|---|
| 바깥 테두리(1칸) | 이웃 몸 색 ×0.45 | 이웃 몸 색을 푸른 쪽(250°)으로 돌려 어둡게. 빛 쪽 테두리(몸의 위·왼쪽에 붙은 칸)는 밝기 −0.30, 그림자 쪽(아래·오른쪽)은 −0.42 |
| 빛 받는 가장자리(몸 칸 중 위나 왼쪽이 바깥) | 맨 위 칸만 흰빛 18% | 노란 쪽(50°)으로 돌려 밝기 +0.10 |
| 그림자 가장자리(아래나 오른쪽이 바깥) | ×0.8 | 푸른 쪽으로 돌려 밝기 −0.12 |
| 짙은 칸(밝기 < 60) | 그대로 | 그대로 |
| 검은 요괴(몸의 60% 넘게 짙음) | 밝은 테두리 `REFINE_RIM` | 그대로 |
| 안에 갇힌 빈칸 · 1칸 골목 | 비움 | 그대로 |
| 짙은 색에만 닿은 바깥 칸 | 테두리 없음 | 그대로 |
| 작은 무늬 보호(새 규칙) | 없음 | 상하좌우 이웃 넷 중 셋 이상이 자기와 다른 색인 몸 칸(입·볼·단추)은 색을 바꾸지 않음 |

색조 이동은 목표 쪽으로 **최대 35%**만 돌리고, 밝기 변화가 클수록 채도를 조금 줄인다(최대 −50% × 변화량). 밝기 수치는 시작값이며, 전후 비교 캡처를 보고 맞춘다. 맞춘 최종값은 이 표를 고쳐 적는다.

**캡처를 보고 맞춘 최종값 (2026-11-05)** — 첫 캡처에서 연한 흰 옷(백여우·백두야차) 테두리가 분홍으로, 주황·갈색 테두리가 빨강·새까맣게 됨:
- 색조는 목표 쪽으로 최대 35%이되 **15°까지만**
- **색 짙기(최대−최소)가 원래보다 커지지 않게** 채도를 묶음(연한 색이 물들지 않게)
- 테두리 밝기는 빼기 대신 **곱**: 빛 쪽 × 0.55 · 그림자 쪽 × 0.40(예전 × 0.45와 비슷한 짙기, 짙은 색이 새까맣게 되지 않음). 색조·채도 세기는 −0.4로
- 가장자리 밝기는 그대로 +0.10 / −0.12

빛 쪽 테두리와 그림자 쪽 테두리를 고르는 법: 바깥 칸의 몸 이웃 가운데 아래나 오른쪽에 있는 몸(= 칸이 몸의 위·왼쪽)이면 빛 쪽, 위나 왼쪽에 있는 몸이면 그림자 쪽으로 본다. 둘 다면 빛 쪽으로 친다.

## 4. 구조

- 바뀌는 곳: `src/js/01_sprites.js`의 `refinePix(src,w,h)`. 돌려주는 값 `{data,w,h}`는 그대로다.
- 새 도구(같은 파일): `rgbToHsl(r,g,b)→[h,s,l]`, `hslToRgb(h,s,l)→[r,g,b]`, `hueShift(rgb,dl)→rgb`(dl < 0이면 푸른 쪽, > 0이면 노란 쪽).
- 다듬은 그림은 처음 쓸 때 한 번 만들어 둔다(`variants()`의 `R1`, 지금과 같음). 플레이 중 한 프레임에 드는 시간은 늘지 않는다.
- 저장 형식은 바뀌지 않는다(`meta.set.refine` 그대로). 옛 저장 옮기기는 필요 없다.

## 5. 성능

- 늘어나는 것은 그림을 처음 만들 때의 시간뿐이다.
- 기준: `tests/browser/refine_perf.py`(CPU 4배 느림)가 v20.4 값의 **1.5배 이내**여야 한다.
- 넘으면: `hueShift` 결과를 「색 + 변화량」마다 한 번만 계산해 기억해 둔다.
- `vfx_perf` 프레임 시간은 v20.4와 같아야 한다(차이 ±5% 이내, 흔들림).
