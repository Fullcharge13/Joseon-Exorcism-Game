# 견습 동행 작업 계획

**목표**: 2부(북으로 간 판)에 견습 하나(소년 근접 / 소녀 원거리)를 더해 11막부터 새로 키울 거리를 만든다.
**구조**: 새 파일 `src/js/08c_apprentice.js`에 견습의 데이터(`AWD` 무기 6, `APD` 보패 4, `AP_KIDS`)와 동작(`apStart`·`apTick`·`apStage`·`drawAp`·카드 `apOpts`/`apDecorate`/`apApply`)을 모은다. 엔진은 부르는 줄만 더한다: `update`(apTick) · `nextStage`(apStage) · 그리기(drawAp) · `genOptions`/`decorate`/`applyOpt` · `buildHTML`(칸) · 전갈의 「북으로」.
**설계서**: `docs/specs/2026-11-23-견습-동행-설계.md`

## 전체 제약
- 피해는 `hurt(e, dmg, kb, fx, fy, true)`로만, `HSRC = 'ap:' + id`. 판 난수 `rand()`, 그림 `vrand()`.
- 견습이 없는 판(1부만·원정·설화)은 그대로 — `act2_off_same` 지문 `3,8311,39,268,428`.
- 견습은 판 안 상태(`G.ap`)만. 저장에는 `meta.ap = {seen}`(장면을 본 적) 기본값만.

## Review Focus
1. 레벨업 창에서 견습 카드를 고른 뒤 `reroll`·`ban`이 견습 카드를 깨뜨리지 않는지 → `ap_cards`
2. 기절 중 막이 바뀌거나 끝없는 밤으로 넘어갈 때 → `ap_down`
3. 견습이 숨은 막에서 보스 처치·주막·결말 → `ap_down`
4. 견습 공격이 보스 초당 상한(`BOSS_CAP`)을 지키는지(hurt를 거치므로) → `ap_fight`
5. 화면 폭 390에서 칸 줄 넘침 → 브라우저 캡처

### 작업 1: 등장과 고르기
- 시험 `ap_flow`: 10막 평정 → 북으로 → (처음) 장면 2쪽 → 고르기 창 두 장 → 「복돌」 → `G.ap.kid==='boy'`, 무기 `mokgeom` Lv1, 체력 120. 두 번째 판은 장면 없이 고르기만. 북으로 안 간 판·원정에는 `G.ap` 없음.
### 작업 2: 싸움
- 시험 `ap_fight`: 무기 6종을 하나씩 쥐여 요괴 10마리 곁에서 5초 → 처치·피해>0, `G.rs.dmg['ap:<id>']`>0. 보스에게도 상한 지킴.
### 작업 3: 레벨업 카드
- 시험 `ap_cards`: 견습 있으면 선택지 가운데 견습 카드 정확히 2. 올리기·바꾸기·보패 새로/올리기/바꾸기·모두 최대 뒤 단련. 다시 굴리기 뒤에도 2.
### 작업 4: 쓰러짐
- 시험 `ap_down`: 체력 0 → 기절, 퇴마사가 원 밖이면 진행 그대로, 안이면 5초 뒤 체력 50%. 세 번째 → 숨음(피해 0). `nextStage` → 체력 가득·0번·나타남.
### 작업 5: 화면·그림·번역·균형·기록
- 칸 HTML, 머리 위 막대, 기절 별, 소년·소녀 모습(`lk`). 간체. 자동 플레이(봇이 기절한 견습 곁으로) · 같은 장면 비교로 견습 피해 비중 15~25%. LOG·README·안내서.
