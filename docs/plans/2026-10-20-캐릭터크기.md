# 캐릭터·요괴 크기 · 작업 계획 (v17.1)

- **목표**: 보이는 넓이와 판정은 그대로 두고, 캐릭터·요괴 그림만 2배로 깔끔하게 키우는 설정을 넣는다(1.5배는 작업 5에서 뺌).
- **구조**: 크기가 기본이 아닐 때만 그리기 판을 2배 정밀로 만들고, 「몇 배로 그릴지」는 `entK(e)` 한 함수가 정한다. 느려짐 감지가 걸리면 먼저 이 설정을 끈다.
- **기술**: `index.html` 한 장(캔버스 2D). 시험은 `tests/harness.js`(Node 가짜 화면)와 Playwright.
- **설계 문서**: `docs/specs/2026-10-20-캐릭터크기.md`
- **지킬 것(설계에서 그대로)**: 단계 `1 | 2`(기본 1, 처음 계획은 `1 | 1.5 | 2`) · 보스 최대 1.5 · 이무기·어둑시니·그슨대 1 · 판정(`P.r`, `e.r`)·무기·투사체·아이템·장애물·피해 숫자·HUD 그대로 · 절약 모드면 늘 기본 · 느려지면 저장값은 두고 이번 실행만 끔 · 저장 판 번호 그대로 · 화면 버전 `v17.1`, `sw.js` `joseon-v17.1`
- **바뀐 것(2026-10-20)**: 작업 5에서 1.5배가 홀수 화면 배율에서 깔끔하지 않음을 확인 → 사용자 결정으로 단계를 `1 | 2`로 줄임. 아래 1.5배 관련 시험은 2배로 바꿔 진행.
- **커밋**: 작업 중에는 하지 않는다. 마무리 보고 뒤 허락을 받는다.

## 검토 때 특히 볼 곳 (깨질 가능성 순)

1. **기본 크기에서 화면이 조금이라도 달라짐**: 2배 정밀이 꺼진 상태는 v17.0과 픽셀까지 같아야 함 → 작업 5 `ent_size.py` 「기본 = v17.0 동일」 검사
2. **2배 정밀에서 빠뜨린 그림**: 그리기 판 밖으로 나가거나 반만 그려지는 것(제목 배경, 어둠 막, 가장자리 화살표, 화면 흔들림) → 작업 5 캡처 직접 확인, 작업 2 `ent_size` 「그리기 판 크기」
3. **머리 위 막대·표식이 커진 그림 속에 묻힘** → 작업 3 `ent_size` 「표식 높이」
4. **느려짐 감지가 크기를 끈 뒤 곧바로 절약 모드까지 감**(감지를 다시 시작하지 않음) → 작업 4 `ent_perf`
5. **게임 중 설정을 바꿨을 때 그리기 판 크기가 안 바뀜** → 작업 1·2 `ent_size` 「설정 바꾸면 resize」

## 작업 2 · 2배 정밀 그리기 판

- **파일**: `index.html`(`resize` 3337행, `render` 3479행, `blit` 3596행, `applyPerf` 1735행)
- **만드는 것**: `let entOff=false;` · `function hdOn(){return meta.set.ent>1&&!LOW&&!entOff;}` · `resize()`에서 `const k=hdOn()?2:1; buf.width=W*k; buf.height=H*k;` · `render()` 맨 앞 `b.setTransform(hdOn()?2:1,0,0,hdOn()?2:1,0,0)` · `blit()`은 `buf.width×buf.height`를 옮김 · `applyPerf()` 뒤에는 `resize()`가 늘 따른다(이미 그런지 확인)
- **나눠 줄 것**: `hdOn() → boolean`
- [ ] 시험: `ent` 1 → `buf.width===W`. `ent` 1.5 → `buf.width===2*W && buf.height===2*H`. 절약 모드(`meta.set.perf='low'`) → `buf.width===W`
- [ ] 시험: `W`, `H`, `S`는 `ent`가 바뀌어도 그대로
- [ ] 실패 확인 → 구현 → 통과

## 작업 3 · 그림 배율 `entK`

- **파일**: `index.html`(요괴 그리기 `render` 안 `drawSpr` 줄, 표식·정예 막대·그림자 줄, `heroBox` 3414행, `drawHeroBody` 3416행, `drawHpBar` 3418행, `drawPet` 2542행, `drawJW` 3431행) · 시험 `tests/unit/ent_size.test.js`(이어서)
- **소비**: 작업 2 `hdOn()`
- **만드는 것**: `function entK(e){if(!hdOn())return 1;const k=meta.set.ent;if(!e)return k;if(e.boss){const pk=EN[e.kind].proc;if(pk==='imugi'||pk==='eoduk'||pk==='geuseunde')return 1;return Math.min(k,1.5);}return k;}` (인자가 없으면 플레이어·펫·전우치)
- [ ] 시험(가짜 그리기 판의 `drawImage` 호출을 기록): `ent` 2 → 플레이어 그림 폭 = `ps.w*2`. 일반 요괴 폭 = `s.w*e.sc*2`. 보스 폭 = `s.w*e.sc*1.5`. 이무기 보스는 따로 그리는 함수가 그대로. 투사체·아이템 `drawImage` 폭은 `ent` 1일 때와 같음
- [ ] 시험: `P.r`, 요괴 `e.r`는 `ent` 1·2에서 같음. 요괴를 플레이어에게서 `P.r+e.r+1` 떨어뜨려 두면 `ent` 2에서도 맞지 않음(그림은 겹쳐 보여도 판정은 그대로)
- [ ] 시험: 머리 위 표식(표적 `e.mark`)의 y가 `e.y - s.hgt*e.sc*entK(e)` 위쪽
- [ ] 실패 확인 → 구현 → 통과
