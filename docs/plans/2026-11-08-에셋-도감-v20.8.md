# 에셋 도감 v20.8 작업 계획

**목표**: 코드로 그린 그림 전부를 게임의 그리기 함수로 뽑아 도감 페이지(`docs/assets/`)와 README 그림(`docs/img`)을 명령 한 번으로 만든다.
**구조**: `tools/assets_list.js`(게임 위에 얹어 「무엇을 어떻게 그릴지」 목록과 그리기)를 `tools/assets.py`가 Playwright로 게임 페이지에 넣어 PNG·`assets.json`·대표 시트를 쓴다. 도감 페이지는 `assets.json`을 읽는 한 장 HTML.
**도구**: Python + Playwright(설치됨) · Node 하네스(단위) · 게임 `index.html`(빌드본)
**설계서**: `docs/specs/2026-11-08-에셋-도감-v20.8.md`

## 지킬 것
- 게임 코드(`src/js`)는 고치지 않음(판 번호 `GAME_VER`와 `sw.js`의 도감 캐시 제외만) · 커밋은 사용자 허락 뒤 · 올리기 전 GitHub 최신 확인
- 시험 먼저 · 브라우저 시험·도구는 하나씩(기계가 다시 시작됨)
- 같은 입력 → 같은 파일(PNG에 시각·메타 넣지 않음)

## 살필 것 (시험이 놓치기 쉬운 순서)
1. 접두 규칙이 틀려 README 그림이 엉뚱한 그림으로 덮임 → 작업 2 「지금 파일과 견주기」: 다른 것은 덮기 전에 모두 보고, 화면으로 확인한 뒤에만 씀(첫 실행은 `--check`로 보고만)
2. 다듬기 켬 그림이 설정(`meta.set.refine`)에 따라 바뀜 → 작업 2에서 `raw`/`ref`를 직접 집어 설정과 무관하게
3. 같은 id가 두 표에 있음(`baekho`는 축복·짝 축복 등) → 작업 1 「종류+id로 유일」
4. 도감 페이지가 `file://`에서는 `assets.json`을 못 읽음 → 작업 3: 페이지에 목록을 함께 넣음(`assets.js`), JSON은 다른 도구용
5. 휴대폰에서 450칸 격자가 느림 → 작업 3 `loading="lazy"` · 시험에서 처음 그리기 시간 잼
