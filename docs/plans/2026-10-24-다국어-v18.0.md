# 다국어 v18.0 · 작업 계획 (구조 바꾸기, 플레이어에게 바뀌는 것 없음)

- **목표**: `src/`로 나누고 한국어 문구를 표로 옮겨, v18.1에서 간체를 넣을 자리를 만든다. 한국어 화면은 v17.5와 같다.
- **구조**: `src/shell.html` + `src/js/NN_*.js` → `build.py` → `index.html`. 문구는 **한국어 원문을 열쇠로** `_t('원문',{변수})`(2026-10-24 설계 3-2 수정: 처음 안의 `ko.js`·이름 열쇠·`data-t`는 쓰지 않음), 데이터 표는 원문을 열쇠로 덧씌우기. 이름이 `_t`인 까닭은 `tools/README.md`.
- **기술**: Python 3(빌드), Node(가짜 화면 시험), Playwright
- **설계 문서**: `docs/specs/2026-10-24-다국어.md` · **용어집**: `docs/i18n/용어집.md`
- **지킬 것**: 배포물은 `index.html` 한 장 · 나누기 직후 v17.5와 바이트까지 같음 · 저장 판 번호 그대로 · 중국어 단추는 v18.1까지 숨김 · 화면 버전 `v18.0`, `sw.js` `joseon-v18.0`
- **커밋**: 마무리 보고 뒤 허락

## 검토 때 특히 볼 곳

1. 나누다가 한 줄이라도 빠지거나 순서가 바뀜 → 작업 1 `build.py --check`(v17.5와 바이트 비교)
2. 옮긴 문구의 끼워 넣기·조사가 달라짐(「을/를」, 숫자 자리) → 작업 3 `i18n_josa`, 작업 5 `i18n_ko_same.py`
3. 언어 장치가 저장을 건드림(옛 저장에서 진행이 사라짐) → 작업 4 `i18n_lang`
4. 시험 도구가 `src`를 몰라 옛 파일을 읽음 → 모든 시험은 `build.py` 뒤 `index.html`로

## 실행 결과와 v18.1로 넘긴 것 (2026-10-24)

- 작업 1~3·5·6은 위 수정된 방식으로 끝냄. 작업 2의 「남은 문구 0」은 `node tools/i18n_wrap.js`가 「감쌀 곳 0」을 보고하는 것으로 확인한다(`i18n_extract.py`는 표·감싼 문구까지 세는 대략의 양 보기).
- 작업 4 중 **설정의 「언어」 칸, 언어를 바꾼 뒤 열린 화면 다시 그리기**는 중국어 단추를 공개하는 v18.1로 넘긴다(v18.0에서는 언제나 한국어).
- 검토자 지적 가운데 v18.1로 넘긴 것:
  - 기록관이 출정마다 완성된 글(`cls`·`where`)을 저장 → 언어를 바꾸면 옛 기록이 다른 언어로 남고, `clsT`의 비교가 어긋나 「 · 선비」가 겹칠 수 있음 → 아이디를 저장하고 보여 줄 때 글을 만들도록(옛 저장 옮기기 포함)
  - `l10nDom`이 처음 본 글을 원문으로 기억 → 코드가 나중에 바꾼 글자를 되돌릴 수 있음, `<title>`은 바뀌지 않음 → 화면 다시 그리기와 함께 고침
  - 큰 HTML 틀의 열쇠에 코드 들여쓰기가 들어 있음, `{p}`…`{p9}` 같은 이름 → 번역하면서 손으로 정리
  - 번역 빠짐은 오류 기록에 실행마다 한 번만 남음 → 빠짐 검사는 v18.1 단위 시험 `i18n_keys`(사전 전수 비교)로
  - 오류 기록 글(`diagNote`)은 한국어로 둠(개발자에게 보내는 글). 설계 2장의 「오류 기록 화면」은 화면의 단추·안내만 번역하는 것으로 좁힘
- v18.0에서 바로 고친 것: 조사 고르는 코드 속 「을·를·이·가·로·으로」가 번역 함수로 감싸져 있던 것(간체에서 엉뚱한 글자가 붙을 뻔함) → 감싸지 않음 / 간체 문구에는 한국어 조사를 붙이지 않음 / 간지 한글 한 글자(신=辛·申)는 사전으로 못 바꾸므로 언어별 한자 표로 / `build.py`가 `</script` 끼임·줄바꿈·합친 스크립트 문법을 검사 / 감싸기 도구가 원문 속 `{ }`를 만나면 멈춤
